Challenge & Approach

Why LOCALOCR?

Turning hours of video into searchable, organized data — without the cloud

The Problem

Users have hours of video content — financial news broadcasts, technical presentations, recorded lectures — containing critical screens buried in the footage.

Manually scrubbing through video to find specific frames is tedious, error-prone, and doesn't scale. Cloud-based solutions raise privacy and cost concerns.

Existing tools either require internet connectivity, lack multi-language support, or can't handle Indic scripts like Hindi/Devanagari.

The Solution

LOCALOCR automatically extracts frames at configurable intervals, runs multi-engine OCR, matches keywords, and organizes everything into categorized folders.

Everything runs 100% locally on your Mac — leveraging Apple Neural Engine, Metal Performance Shaders, and multi-core CPU parallelism.

~2-3 min to process a 1-hour video (English fast mode)

Under the Hood

Technical Highlights

Pluggable OCR Engine System

Abstract base class (OCREngine ABC) pattern. Apple Vision, EasyOCR, and Composite ship out of the box. Add a new engine by subclassing and registering in the factory.

Script-Aware Deduplication

Composite engine merges Latin text from Apple Vision + Devanagari from EasyOCR without duplicating numbers or English characters across engines.

Hardware-Aware Parallelism

Apple Vision uses ProcessPoolExecutor with spawn context (bypasses GIL + PyObjC). EasyOCR uses a global lock. Composite runs both concurrently on different hardware.

Two-Pass LLM Extraction

Phase 1 extracts structured JSON stock picks from frames. Phase 2 retries null fields with partial context, filling gaps the first pass missed.

Graceful Interrupt Handling

A threading.Event is checked before every Ollama API call. On Ctrl+C, partial Phase 1 data is always saved to disk — no work is lost.

Unicode-Safe Organization

NFC normalization preserves Devanagari matras and combining marks in folder names. Hindi keywords like सेठी/ render correctly on disk.
