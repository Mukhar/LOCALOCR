PyTorch-backed multilingual OCR (80+ languages including Hindi/Devanagari). Thread-safe via global _readtext_lock. Readers cached per language combo. Confidence filtering.

CompositeEngine

src/ocr/composite_engine.py

Runs Apple Vision + EasyOCR concurrently via ThreadPoolExecutor. Script-aware merge: primary (Apple Vision) keeps all lines, secondary (EasyOCR) contributes only non-Latin text. Deduplicates exact matches.

Apple Vision — Multiprocessing (spawn)

Main Process

OCR Dispatcher creates ProcessPoolExecutor with spawn context. Distributes frames via pool.map() with chunked dispatch.

Orchestrator
Worker 1

Own Python GIL, own PyObjC runtime. Initializes fresh AppleVisionEngine. Warms up with first frame. Submits to ANE.

ANE Submission
Worker 2

Overlaps CPU image decode of next frame with ANE inference on current frame. True hardware parallelism.

ANE Submission
Worker N

Configurable via apple_vision_workers. Benchmarked: 3× throughput at 4 workers vs single-threaded.

ANE Submission

Why spawn not fork? PyObjC Objective-C runtime is not fork-safe. Each worker must initialize its own Vision Framework handle.

EasyOCR — Thread-Safe Serial

Global Lock

_readtext_lock = threading.Lock() serializes all readtext() calls. PyTorch model is not thread-safe for concurrent inference.

Serial Execution
Reader Cache

EasyOCR Reader instances cached per language combo in module-level _readers dict. Models downloaded once (~100MB) to ~/.EasyOCR/.

Lazy Singleton

Composite — Concurrent Engines

ThreadPoolExecutor

Apple Vision and EasyOCR run simultaneously via thread pool. No resource contention — they use different hardware.

Concurrent
Apple Vision → CPU/ANE

Processes Latin/English text using Apple Neural Engine. Primary engine — all lines kept verbatim.

Primary
EasyOCR → MPS GPU

Processes Devanagari/Indic text using Metal Performance Shaders GPU. Secondary — only non-Latin lines kept.

Post-OCR — LLM Pipeline Threading

Phase 1 & 2

Sequential Ollama API calls (one image at a time). Each call checks _stop_event before proceeding. Partial data always saved on interrupt.

Sequential + Interruptible
Phase 3 — Background Thread

HTML dashboard built in ThreadPoolExecutor(max_workers=1) daemon thread. Never blocks the main pipeline. 120s timeout.
